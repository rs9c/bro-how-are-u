## 立项意义

一、项目背景

据国家统计局 2024 年统计公报（https://www.stats.gov.cn/sj/zxfb/202502/t20250228_1958817.html），2024 年末我国 60 岁及以上人口 31031 万人，占总人口的 22.0%；其中 65 岁及以上人口 22023 万人，占 15.6%，我国已进入中度老龄化社会。摔倒则是老年人最主要的伤害风险之一：中国疾控中心慢病中心明确指出，“在我国，跌倒是老年人因伤害到医疗机构就诊的首位原因，也是 65 岁及以上老年人因伤害死亡的首位原因”（https://ncncd.chinacdc.cn/zxdt/202506/t20250611_311214.htm）。世界卫生组织的统计也显示，跌伤是全球非故意伤害死亡的第二大原因，每年约 68.4 万人因此死亡，其中 60 岁以上成年人所占比例最大（https://www.who.int/zh/news-room/fact-sheets/detail/falls）。

摔倒风险与身边是否有人照应密切相关。一项覆盖 2013 年全国 31 个省（自治区、直辖市）98629 名 60 岁及以上社区居民的调查显示：我国老年人 6 个月内跌倒发生率为 8.0%，其中无配偶老年人（11.0%）明显高于有配偶老年人（7.0%）；在发生过跌倒的老年人中，有 52.6% 因此受伤（http://chinaepi.icdc.cn/zhlxbx/ch/reader/view_abstract.aspx?file_no=20180410&flag=1）。这组数字提示：摔倒并不只发生在无人照顾的老人身上，但缺少身边人照应的老人，摔倒风险更高，被发现得更晚，后果也更重。

更重要的是，摔倒本身多数并不直接致命，真正的危险来自摔倒之后长时间无法自行起身、又无人发现。摔倒后在地上滞留的时间，很大程度上取决于能否被及时发现，而这一点目前最难保证，也正是本项目要压缩的环节。早在 1981 年，《英国医学杂志》（BMJ）发表的一项针对 125 名 65 岁以上居家摔倒者的调查发现，其中 20 人躺在地上超过 1 小时，他们中有一半在摔倒后 6 个月内死亡；该研究还发现，跌倒者一年内的死亡率是同年龄、同性别对照组的 5 倍，并指出居家跌倒往往是老年人健康状况已经较差的信号（https://www.bmj.com/content/282/6260/266）。需要说明的是，该研究只能说明摔倒后长时间无人发现往往后果严重，不能证明倒地时间越长就必然导致死亡；我们将其作为问题严重性的依据，而非因果证明，也不声称报警及时就一定能避免严重后果。本项目要做的事情十分具体：把“从摔倒到被发现”的时间从几小时压缩到几秒，使其不再成为决定后果的关键因素。

综合来看：人工巡查依赖持续的人力与财力投入，可穿戴设备要求老人改变生活习惯，专用传感器需要较高的硬件改造费用；而全国范围内已经建成的大量监控摄像头，目前基本只承担“事后回放”的职能。本项目要做的，就是把这些摄像头的职能从“事后回放”扩展为“实时预警”。

需要说明的是，卫生间等私密空间不适合安装摄像头，这部分盲区不在本方案的覆盖范围内，仍需依靠其他监护方式兜底；本项目面向的是家庭与养老机构中最主要的活动区域，可与可穿戴设备、紧急呼叫等监护手段配合使用。

三、项目价值

1、社会价值：为独居老人家庭、社区养老服务中心、养老机构值班室提供一套低成本、非接触的摔倒预警手段，把“从摔倒到被发现”的时间从数小时压缩到数秒，为救援争取时间，进而降低摔倒后的致残与死亡风险。

2、经济价值：方案为纯软件形态，复用既有摄像头与普通计算机，无需新增传感器、无需布线改造，智慧养老改造的边际成本趋近于零，便于在预算有限的家庭与基层机构中推广。

3、技术价值：验证“轻量目标检测模型+连续多帧判断”在低算力条件下的可行性，形成一套可复用的参考实现（帧序列—检测—判断—报警）。这套实现不局限于摔倒检测，后续可以迁移到逗留、闯入、攀爬等其他异常行为识别任务。

## 创新点

1、存量摄像头复用、纯软件旁路部署：系统不新增任何传感器，直接接入已有的视频来源（USB 摄像头、本地视频、网络摄像头），以软件方式旁路运行，不改变原有设备的安装方式与运行策略，接入时仅需一路可用的视频流。老人无需佩戴设备，机构无需布线改造，部署成本趋近于零。

2、“单帧检测+多帧确认”的两步判断（抑制误报的关键设计）：摔倒与蹲下、坐下、弯腰拾物、躺卧休息等动作在单帧画面中高度相似，仅凭单帧检测极易产生误报。本系统在 YOLOv8 检测结果的基础上增加一层轻量的多帧判断：①检测框宽高比发生突变（由竖长变为横宽）；②检测框中心点高度较历史均值骤降；③最近一段时间内连续命中的帧数达到阈值。三项条件同时满足时才触发报警。这一设计不增加训练成本，却能显著减少蹲下、系鞋带等动作引发的误报。判断逻辑示意如下：

3、参数全可调、报警可解释：置信度阈值、连续帧数、报警冷却时间、静音开关均可在界面实时调整；界面同步显示检测框、类别与置信度，并记录触发报警的具体画面及日志，可供回溯。

## 研究内容

> table 3

1、开发环境与基线。统一 Python 版本与依赖（PyTorch、Ultralytics、OpenCV、FastAPI 等），加载 YOLOv8 官方预训练权重，跑通“输入图片—推理—输出带标注框的结果”最小闭环；同时实测三台带 RTX 5060 的机器和一台无独立显卡的机器各自的推理耗时与显存占用，弄清本地算力的最低要求。这一步的结果将作为后续所有实验的基准线。

2、数据与标注。筛选与清洗公开数据（例如 UR Fall Detection Dataset、Le2i、Multiple Cameras Fall Dataset 及公开平台上的跌倒检测数据）；同时由团队成员在宿舍、走廊、楼梯口等场景拍摄摔倒、坐下、蹲下、弯腰拾物、躺卧、快走等动作，覆盖昼夜光照、远近景与正侧视角，并有意识地加入遮挡与多人同框画面，弥补公开数据集的空缺。所有数据统一为 YOLO 标注格式，按 7:2:1 划分训练集、验证集与测试集，并形成一份可复核的标注规范。

3、模型训练与评测。以 YOLOv8s 为主模型，对输入分辨率、学习率、每次训练的数据量与数据增强方式做对比实验，观察不同设置下识别效果的变化；不断优化数据集、模型以及判断阈值，提高整体准确率，降低漏报率（摔倒却没报警）与误报率（没摔却报警）。

4、多源输入与推理服务。图片、视频文件、摄像头三类输入的数据形态、节奏与异常情况各不相同，统一抽象为“帧序列”后，共用同一套处理流程；研究抽帧与丢帧策略对报警延迟的影响、预处理与推理之间的分工，以及前后端的接口约定与异常处理规则的设计，在流程复用与实时性之间寻找平衡。

5、界面与报警交互。研究检测框、类别、置信度与事件记录的组织方式，弄清使用者能否一眼看清画面中发生了什么；同时研究报警方式的选择、冷却机制的设置与参数面板的详细程度，在“漏报”和“误报”之间寻找平衡，并验证非技术背景的使用者能否自行调整。

6、系统集成与场景测试。把模型、服务与界面整合成可一键启动的完整系统，用测试用例覆盖三种输入方式与常见异常，并在不同光照、遮挡、多人、远近景条件下反复测试，弄清系统的能力边界，最后把适用条件与已知局限如实写进文档。

## 研究路线

总体研究思路是“先跑通、再跑准、最后跑稳”：先用官方权重跑通从输入到报警的完整流程，保证系统可运行；再通过数据与微调提高识别准确率；最后通过连续多帧判断与参数调整抑制误报，保证运行稳定。技术路线如下：

## 具备的研究条件

1、团队与指导条件。项目组共 4 人，均为重庆大学大一本科生，由队长负责统筹与任务分配；项目配备 1 名指导老师，负责技术路线把关与疑难问题答疑；团队成员学习能力强、课余时间相对充足，4 人均具备编程基础，并已形成查阅官方文档与阅读开源项目代码的学习习惯。项目工作按数据与标注、模型训练与评测、后端服务、界面与交互四个方面推进，由队长根据各人情况分配任务并跟踪进度；各环节互相评审、交叉参与，避免任何一项工作仅由一个人承担。

2、硬件条件。团队 4 人中有 3 人的笔记本电脑配备 RTX 5060 独立显卡（8GB 显存），足以在本机完成 YOLOv8s 的微调训练与实时推理，项目全程使用自有设备完成训练，不依赖云端算力服务；另 1 台无独立显卡的机器用于前端开发、文档写作与低负载调试。此外配备 USB 摄像头一枚用于实时输入调试，手机可用于采集自建数据集；数据、模型权重与实验记录保存在本地磁盘，并定期备份到移动硬盘。

3、软件与平台条件。项目完全基于开源生态，不产生软件授权费用：算法侧使用 Python、PyTorch、Ultralytics YOLOv8、OpenCV；服务侧使用 FastAPI；界面侧使用 Node.js 与 Vue 3（配合 Vite 构建、Naive UI 组件库）；开发工具使用 VS Code、Git 与 GitHub 进行版本管理。Ultralytics 官方文档、GitHub 上的开源摔倒检测项目、B 站与 CSDN 上有大量可参考的教程与代码，学习成本可控。

4、数据条件。公开渠道可获得若干成熟的行人摔倒数据集，例如 UR Fall Detection Dataset、Le2i Fall Detection Dataset、Multiple Cameras Fall Dataset 及公开平台上的跌倒检测数据集，可满足模型微调的基本样本量需求；同时由团队成员补充拍摄模拟摔倒与近似动作视频，以贴合本项目的实际应用场景。二者结合，可在不依赖真实患者影像的前提下构建训练与评测数据。

5、文献与资料检索条件。世界卫生组织、国家统计局、中国疾控中心等机构公开的统计与健康资料可免费查阅；Ultralytics 官方文档与 GitHub 上的开源项目提供了从数据标注、模型训练到部署的完整说明。

6、时间与经费保障。项目周期约 9 个月，起止时间以平台要求填写的时间为准；4 人可利用课余时间与周末集中推进。项目经费按学校 SRTP 经费管理办法使用。

## 预期研究目标

总目标：交付一个可运行、可复现、可演示的纯软件摔倒识别与报警原型。接入已有摄像头即可工作，识别到摔倒行为时在画面中标注位置、显示置信度并触发声音报警，同时配套完整的开发与使用文档，形成一份结论可靠的结题报告。
