# 立项意义

## 一、项目背景

跌伤是全球非故意伤害死亡的第二大原因，每年约 68.4 万人因此死亡。即使不致命，每年仍有约 3730 万例跌伤严重到需要接受治疗，全球每年因跌倒损失 3800 多万残疾调整生命年（https://www.who.int/zh/news-room/fact-sheets/detail/falls）。

跌倒在老年人身上的后果最重。中国疾控中心慢病中心指出，"在我国，跌倒是老年人因伤害到医疗机构就诊的首位原因，也是 65 岁及以上老年人因伤害死亡的首位原因"（https://ncncd.chinacdc.cn/zxdt/202506/t20250611_311214.htm）。在发生过跌倒的老年人中，有 52.6% 因此受伤（http://chinaepi.icdc.cn/zhlxbx/ch/reader/view_abstract.aspx?file_no=20180410&flag=1）。

而跌倒不只威胁着老年人。中国儿童青少年（小于 20 岁）跌倒标化发病率在 1990—2021 年间呈非线性波动，中小学生跌倒伤害人数发生率为 8.03%（http://chinaepi.icdc.cn），0—4 岁和 5—14 岁人群跌倒造成头部受伤的比例分别高达 62.39% 和 42.62%。职业人群中，工作相关有伤害跌倒年发生率为 3.8%，美国 1998 年有超过 55 万例职业跌倒伤害在急诊接受治疗（https://stacks.cdc.gov）；在中国，跌倒等是意外伤害住院的首要原因（约占 74%），30—69 岁住院伤害患者中跌倒占 41.84%（https://link.springer.com）。以上数据表明，摔倒风险贯穿全年龄段，实时摔倒检测与预警不仅服务于老年监护，也能为儿童安全、行人保护、职业安全等场景提供支持。

摔倒本身多数并不直接致命，真正的危险来自摔倒之后长时间无法自行起身、又未能被及时发现并得到救助。针对这点，本项目旨在提供一种非接触、低成本、具备主动识别与自动报警能力的智能技术手段。

## 二、现有方案的局限

| 方案                               | 需要佩戴/改造        | 覆盖范围                     | 部署成本         | 实时预警能力 | 主要短板                     |
| ---------------------------------- | -------------------- | ---------------------------- | ---------------- | ------------ | ---------------------------- |
| 人工巡查                           | 否                   | 受人力限制，无人值守时段失效 | 人力成本持续投入 | 差           | 无法全时段覆盖；事发无记录   |
| 可穿戴设备                         | 需长期佩戴、定期充电 | 佩戴者                       | 一般             | 好           | 依从性差；佩戴不适感可能较强 |
| 专用传感器（毫米波雷达、压力垫等） | 需改造               | 局部空间                     | 高               | 好           | 造价高，难部署，难以规模化   |
| 现有视频监控                       | 否                   | 视频监控覆盖范围             | 一般（已建成）   | 无           | 无法实时预警，只能靠事后回放 |

综合来看，人工巡查依赖持续的人力与财力投入，可穿戴设备要求佩戴者改变日常习惯，专用传感器需要较高的硬件改造费用；而全国范围内已经建成的大量监控摄像头，目前基本只承担"事后回放"的职能。而本项目致力于将这些摄像头的用途从"事后回放"扩展到"实时预警"。

> 注：本项目面向摄像头已经覆盖或可以覆盖的区域，对于摄像头覆盖不到的位置需配合人工巡查、可穿戴设备、紧急呼叫等其他手段。

## 三、项目价值

1、社会价值：为已经装有摄像头的场所提供一套低成本、非接触的摔倒预警手段。对于养老机构、校园、工地、商场、街道等公共场所，本项目方案可把这些场所中行人"从摔倒被发现"的时间从数小时压缩到几秒内，为救援争取时间，进而降低摔倒后的致残与死亡风险。

2、经济价值：方案为纯软件形态，复用既有摄像头与普通计算机，无需新增传感器或改造已有线路。存量监控系统做智能化改造的边际成本很低，便于在预算有限的基层单位中进行推广。

3、技术价值：验证"轻量目标检测模型+连续多帧判断"在低算力条件下的可行性，形成一套可复用的参考实现（帧序列—检测—判断—报警）。这套实现不限于摔倒检测，后续可以迁移到逗留、闯入、攀爬等其他异常行为的识别任务。

# 创新点

1、存量摄像头复用、纯软件旁路部署：系统不新增任何传感器，直接接入已有的视频来源（USB 摄像头、本地视频、网络摄像头），以软件方式旁路运行，不改变原有设备的安装方式与运行策略，接入时只需要一路可用的视频流。行人无需佩戴设备，场所无需布线改造，部署成本较低。

2、"单帧检测+多帧确认"的两步判断：摔倒与蹲下、坐下、弯腰拾物、躺卧休息等动作在单帧画面中高度相似，仅凭单帧检测极易产生误报。本系统在 YOLOv8 检测结果的基础上增加一层轻量的多帧判断，大致基准如下：

- (1) 检测框宽高比发生突变；
- (2) 检测框中心点高度较历史均值骤降；
- (3) 最近一段时间内连续命中的帧数达到阈值；

用于辅助减少蹲下、系鞋带等动作引发的误报。

    每一帧：YOLOv8 推理 → 检测框（类别，置信度）
        ↓
    置信度筛选（置信度 ≥ 阈值）
        ↓
    连续多帧判断，三项条件同时满足：
      1) 检测框宽高比突变（> 阈值A）——由竖长变横宽；
      2) 框中心高度较历史均值下降（≥ 阈值B）——由较高高度快速下移；
      3) 近期一段时间内连续命中帧数 ≥ 阈值N——排除偶然的误判
        ↓
    满足 ────────────────┬──────────────── 不满足
    触发声音报警          仅显示检测结果，继续观察
    （防抖处理，避免重复报警）

3、参数全可调、报警可解释：置信度阈值、连续帧数、报警冷却时间、静音开关等均可在界面实时调整。界面同步显示检测框、类别与置信度，并记录触发报警的具体画面及日志，可供回溯。

# 研究内容

系统总体架构：

    [输入层]
    图片文件 | 视频文件 | 摄像头（USB / 网络摄像头）
        ↓
    [统一帧序列]
    抽帧策略 → 统一 → 归一化（三种输入共用同一套流程）
        ↓
    [检测层]
    YOLOv8 推理 → 检测框（类别 + 置信度）
        ↓
    [判断层]
    置信度筛选 → 宽高比突变 + 中心高度骤降 + 连续多帧确认 → 报警判断
        ↓
    [服务层]
    后端接口 + 事件记录（时间戳 / 帧图像 / 置信度 / 报警冷却）
        ↓
    [界面层]
    前端界面：检测框叠加 / 置信度显示 / 报警提示 / 参数面板 / 运行日志

1、开发环境与基线。统一 Python 版本与依赖（PyTorch、Ultralytics、OpenCV、FastAPI 等），加载 YOLOv8 官方预训练权重，跑通"输入图片—推理—输出带标注框的结果"这条最小流程；同时实测三台带 RTX 5060 的机器和一台无独立显卡的机器各自的推理耗时与显存占用，弄清本地算力的最低要求，这一步的结果将作为后续所有实验的基准线。

2、数据与标注。筛选与清洗公开数据（例如 UR Fall Detection Dataset、Le2i、Multiple Cameras Fall Dataset 及公开平台上的摔倒检测数据）；同时由团队成员在宿舍、走廊、楼梯口以及操场、道路、广场等室内外场景拍摄摔倒、坐下、蹲下、弯腰拾物、躺卧、快走等动作，覆盖昼夜光照、远近景与正侧视角，并有意识地加入遮挡与多人同框画面，弥补公开数据集的空缺。所有数据统一为 YOLO 标注格式，按 7:2:1 划分训练集、验证集与测试集，并形成一份可复核的标注规范。

3、模型训练与微调。以 YOLOv8s 为主模型，对输入分辨率、学习率、每次训练的数据量与数据增强方式做对比实验，观察不同设置下识别效果的变化，再根据实验结果调整数据构成、模型选择与判断阈值，目标是降低漏报率与误报率。

4、多源输入与数据处理。图片、视频文件、摄像头三类输入的数据形态、节奏与异常情况各不相同，统一抽象为"帧序列"后，共用同一套处理流程；研究抽帧与丢帧策略对报警延迟的影响、预处理与推理之间的分工，以及前后端的接口约定与异常处理规则的设计，从而更好地对输入的数据流进行处理。

5、界面与报警交互。研究检测框、类别、置信度与事件记录等界面元素的高效组织与直观呈现，确保异常事件能被准确、快速地辨识；对比不同报警方式与冷却机制的设置效果，探究参数面板的详细程度与易用性边界；验证非技术背景使用者独立调整参数的可行性，降低系统的使用门槛。

6、系统集成与场景测试。集成模型、服务与界面，构建为可一键启动的完整系统；设计覆盖三种输入方式及常见异常的测试用例；针对不同光照、遮挡、人流与远近景条件，在室内外场景下开展环境适应性与运行稳定性测试，明确系统的能力边界；最终在文档中如实记录适用条件与已知局限。

# 研究路线

总体研究思路：先用官方权重跑通从输入到报警的完整流程，保证系统可运行；再通过数据与微调提高识别准确率；最后通过连续多帧判断与参数调整抑制误报、减少漏报，保证运行稳定。

技术路线：

    需求分析      数据准备         模型训练与调优      系统开发与集成     测试与总结

| 主要风险             | 应对预案                                                                                                                  |

| 样本偏少、标注不一致 | 公开数据集与自录数据互补；制定标注规范并实行双人交叉复核；以未见的场景视频作为独立测试集评估泛化能力。                    |

| 队员课业冲突         | 任务颗粒化拆分，双周进度对齐；数据采集与模型训练等关键任务提前启动；确立"最小可交付版本"作为进度底线。                    |

# 具备的研究条件

1、团队与指导条件。项目组共 4 人，均为重庆大学大一本科生，由队长负责统筹与任务分配；项目配备 1 名指导老师，负责技术路线把关与疑难问题答疑；团队成员学习能力较强，课余时间相对充足；4 人均有编程基础，平时也有查阅官方文档、阅读开源项目代码的习惯；项目工作按数据与标注、模型训练与评测、后端服务、界面与交互四个方面推进，由队长根据每人情况分配任务并跟踪进度；各环节互相评审、交叉参与，避免任何一项工作仅由一个人承担。

2、硬件条件。团队 4 人中有 3 人的笔记本电脑配备 RTX 5060 独立显卡（8GB 显存），足以在本机完成 YOLOv8s 的微调训练与实时推理，项目全程使用自有设备完成训练，不依赖云端算力服务；另 1 台无独立显卡的机器用于前端开发、文档写作与低负载调试。此外配备一个 USB 摄像头用于实时输入调试；手机可用于采集自建数据集；数据、模型权重与实验记录保存在本地磁盘，并定期备份到移动硬盘。

3、软件与平台条件。项目完全基于开源生态，不产生软件授权费用。算法侧使用 Python、PyTorch、Ultralytics YOLOv8、OpenCV 等；服务侧使用 FastAPI；界面侧使用 Vue 3，配合 Vite 构建工具与 Naive UI 组件库进行开发；使用 Git 进行版本控制。

4、数据条件。公开渠道可获取的若干成熟行人摔倒数据集，如 UR Fall Detection Dataset、Le2i Fall Detection Dataset、Multiple Cameras Fall Dataset。这些公开平台上的跌倒检测数据集可满足模型微调的基本样本量需求；同时由团队成员补充拍摄模拟摔倒与近似动作视频，以贴合本项目的实际应用场景。

5、文献与资料检索条件。世界卫生组织、国家统计局、中国疾控中心等机构公开的统计与健康资料，可为本项目提供权威的数据支撑；Ultralytics 官方文档、GitHub 上的摔倒检测开源项目，以及哔哩哔哩、CSDN 等平台的技术教程，可为本项目提供丰富的参考资料。

6、时间与经费保障。项目周期约 9 个月，起止时间以平台要求填写的时间为准；4 人可利用课余时间与周末集中推进。项目经费按学校 SRTP 经费管理办法使用。
