# 立项意义

社会发展的同时老龄化的问题也在不断加深，随之而来的老年人安全看护问题就开始成为家庭、社区和公共服务体系关注的重点。近期国家统计局数据的结果显示，我国60岁及以上人口已经超过了2.8亿，约占总人口20%的比例，而跌倒恰恰是老年人受伤的隐患之一，跌倒严重且长时间无人帮扶的老年人可能出现骨折、颅脑损伤、长期卧床甚至死亡的危险。因此，及时检测出路上跌倒的老年人并报警、提供救援对于保障老年人生命安全、提高其生活质量具有至关重要的意义。

摔倒检测不只用在家居养老场景里，医院、商场、地铁站、公交站、学校、广场这些公共区域中，行人摔倒同样会带来很严重的后果。在人员密集的地方，一个人摔倒可能引发踩踏、拥堵和二次伤害，快速准确地检测出行人摔倒，对公共安全预警和应急响应有很实际的参考价值。

传统摔倒检测方法可以分成三类：穿戴式传感器方法、环境传感器方法和计算机视觉方法。穿戴式方法靠加速度计、陀螺仪这些设备来采集人体运动信息，能拿到比较直接的运动状态数据，可它需要用户一直戴着设备，依从性差，设备续航也有限，维护成本还高。环境传感器方法用红外阵列、压力传感器等设备监测异常行为，适合特定的室内环境，但监测范围不大，部署起来也不灵活。计算机视觉的摔倒检测方法能直接利用已有的监控摄像头来采集视频图像，不用接触人体，覆盖范围广，场景适应性强，它慢慢变成了摔倒检测领域一个重要的研究方向。

# 创新点

1、无接触式识别：系统不新增任何传感器，直接复用现有摄像头，接入已有的视频来源（USB 摄像头、本地视频、网络摄像头），以软件方式旁路运行，不改变原有设备的安装方式与运行策略，接入时只需要一路可用的视频流。识别方式无接触，行人无需佩戴设备；场所无需布线改造，部署成本较低。

2、“单帧检测+多帧确认”的两步判断：摔倒与蹲下、坐下、弯腰拾物、躺卧休息等动作在单帧画面中高度相似，仅凭单帧检测极易产生误报。本系统在 YOLOv8 检测结果的基础上增加一层轻量的多帧判断，用于辅助减少蹲下、系鞋带等动作引发的误报，具体如图 1 所示：

图 1：

    每一帧：YOLOV8 推理 → 检测框（类别，置信度）
        ↓
    置信度筛选（置信度 ≥ 阈值）
        ↓
    连续多帧判断，三项条件同时满足：
        (1) 矩形高宽比 Δ ≥ 阈值 A —— 由竖长变横宽
        (2) 框中心高度突变垂直下降 ≥ 阈值 B —— 主体从高位快速下移
        (3) 最近一段时间内连续命中跌倒 ≥ 帧值 N —— 排除偶然性误判
        ↓
    满足 → 触发声音报警（防抖处理，避免重复报警）
    不满足 → 仅显示检测框，继续观察

3、参数全可调、报警可解释：置信度阈值、连续帧数、报警冷却时间、静音开关等均可在界面实时调整，界面同步显示检测框、类别与置信度，并记录触发报警的具体画面及日志，可供回溯。

1、开发基线。实测三台带 RTX 5060 的机器和一台无独立显卡的机器各自的推理耗时与显存占用，弄清本地算力的最低要求。这一步的结果将作为后续所有实验的基准线。

2、数据与标注。筛选与清洗公开数据（例如 UR Fall Detection Dataset、Le2i、Multiple Cameras Fall Dataset 及公开平台上的摔倒检测数据）；同时由团队成员在宿舍、走廊、楼梯口以及操场、道路、广场等室内外场景拍摄摔倒、坐下、蹲下、弯腰拾物、躺卧、快走等动作，覆盖昼夜光照、远近景与正侧视角，并有意识地加入遮挡与多人同框画面，弥补公开数据集的空缺。所有数据统一为 YOLO 标注格式，按 7:2:1 划分训练集、验证集与测试集，并形成一份可复核的标注规范。

3、模型训练与微调。以 YOLOv8s 为主模型，对输入分辨率、学习率、每次训练的数据量与数据增强方式进行调整，对比实验，观察不同设置下识别效果的变化，再根据实验结果，调整数据集构成、模型选择与判断阈值，目标是降低漏报率与误报率。

4、多源输入与数据处理。图片、视频文件、摄像头三类输入的数据形态、节奏与异常情况各不相同，将其统一抽象为“帧序列”后，共用同一套处理流程：研究抽帧与丢帧策略对报警延迟的影响、预处理与推理之间的分工，以及前后端的接口约定与异常处理规则的设计，从而更好地对输入的数据流进行处理。

5、智能报警。研究检测框、类别、置信度与事件记录等界面元素的高效组织与直观呈现，确保异常事件能被准确、快速地辨识。

6、界面可视化。对比不同报警方式与冷却机制的设置效果，探究参数面板的详细程度与易用性边界；验证非技术背景使用者独立调整参数的可行性，降低系统整体的使用门槛。

# 研究路线

总体研究思路：先用官方权重跑通从输入到报警的完整流程，保证系统可运行；再通过数据与微调提高识别准确率；最后通过连续多帧判断与参数调整抑制误报、减少漏报，保证运行稳定。

开发环境配置：统一 Python 版本与依赖（PyTorch、Ultralytics、OpenCV、FastAPI 等），加载 YOLOv8 官方预训练权重，跑通“输入图片——推理——输出带标注框的结果”这条最小流程。

# 具备的研究条件

1、团队与指导条件。项目组共 4 人，均为重庆大学大一本科生，由队长负责统筹与任务分配；项目配备 1 名指导老师，负责技术路线把关与疑难问题答疑；团队成员学习能力较强，课余时间相对充足；4 人均有编程基础，平时也有查阅官方文档、阅读开源项目代码的习惯。项目工作按数据与标注、模型训练与评测、后端服务、界面与交互四个方面推进，由队长根据各人情况分配任务并跟踪进度；各环节互相评审、交叉参与，避免出现任何一项工作仅由一个人承担的情况。

2、硬件条件。团队 4 人中有 3 人的笔记本电脑配备 RTX 5060 独立显卡（8GB 显存），足以在本机完成 YOLOv8s 的微调训练与实时推理，项目全程使用自有设备完成训练，不依赖云端算力服务；另 1 台无独立显卡的机器用于前端开发、文档写作与低负载调试。此外配备一个 USB 摄像头用于实时输入调试；手机可用于采集自建数据集；数据、模型权重与实验记录保存在本地磁盘，并定期备份到移动硬盘。

3、软件与平台条件。项目完全基于开源生态，不产生软件授权费用。算法侧使用 Python、PyTorch、Ultralytics YOLOv8、OpenCV 等；服务侧使用 FastAPI；界面侧使用 Vue 3，配合 Vite 构建工具与 Naive UI 组件库进行开发；使用 Git 进行版本控制。

4、数据条件。公开渠道可获取的若干成熟行人摔倒数据集，如 UR Fall Detection Dataset、Le2i Fall Detection Dataset、Multiple Cameras Fall Dataset。这些公开平台上的跌倒检测数据集可满足模型微调的基本样本量需求；同时由团队成员补充拍摄模拟摔倒与近似动作视频，以贴合本项目的实际应用场景。

5、文献与资料检索条件。世界卫生组织、国家统计局、中国疾控中心等机构公开的统计与健康资料，可为本项目提供权威的数据支撑；Ultralytics 官方文档、GitHub 上的摔倒检测开源项目，以及哔哩哔哩、CSDN 等平台的技术教程，均可为本项目提供丰富的参考资料。

6、时间与经费保障。项目周期约 9 个月，起止时间以平台要求填写的时间为准；4 人可利用课余时间与周末集中推进。项目经费按学校 SRTP 经费管理办法使用。
