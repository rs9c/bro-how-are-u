# 申报资料

[相关链接](https://sxic.cqu.edu.cn/upm/schedule/12/2768/apply)

> **命题标题 : 行人摔倒智能识别与报警系统**

> 跌倒是65岁以上老年人因意外伤害死亡的首要原因。传统依赖人工巡查或可穿戴设备的方式存在效率低、依从性差等问题，而基于计算机视觉的方法具有非接触、覆盖广、成本低等优势。本项目旨在开发一个纯软件解决方案：基于YOLOv8目标检测模型与Web界面，用户可上传图片、视频或连接摄像头，系统自动识别画面中是否有人摔倒，用标注框标出跌倒位置并触发声音报警，为养老监护和智能安防提供低成本、易部署的摔倒检测工具原型。

> 预期目标：实现一个可运行的软件原型，支持图片、视频、摄像头三种输入方式的行人摔倒检测；掌握Python环境配置和YOLOv8模型的基本使用；能加载预训练权重文件，对输入图像进行推理并输出检测结果；对于检测到的摔倒行为，能在画面中用标注框标出并显示置信度；开发Web界面，支持用户上传文件、实时预览检测结果；当检测到摔倒时，界面触发声音报警提示。

> 预期成果：①可运行的软件原型；②结题报告。

### 立项意义

**一、项目背景**

据国家统计局[1 2024 年统计公报](https://www.stats.gov.cn/sj/zxfb/202502/t20250228_1958817.html)，2024 年末我国 60 岁及以上人口 31031 万人，占总人口的 22.0%；其中 65 岁及以上人口 22023 万人，占 15.6%，我国已进入中度老龄化社会。摔倒则是老年人最主要的伤害风险之一：中国疾控中心慢病中心明确指出，“在我国，跌倒是老年人因伤害到医疗机构就诊的首位原因，也是 65 岁及以上老年人因伤害死亡的首位原因”[2 中国疾控中心慢病中心，2025](https://ncncd.chinacdc.cn/zxdt/202506/t20250611_311214.htm)。世界卫生组织的统计也显示，跌伤是全球非故意伤害死亡的第二大原因，每年约 68.4 万人因此死亡，其中 60 岁以上成年人所占比例最大[4 WHO《跌伤》实况报道，2021](https://www.who.int/zh/news-room/fact-sheets/detail/falls)。

摔倒风险与“身边有没有人”密切相关。一项覆盖 2013 年全国 31 个省（自治区、直辖市）98 629 名 60 岁及以上社区居民的调查显示：我国老年人 6 个月内跌倒发生率为 8.0%，其中无配偶老年人（11.0%）明显高于有配偶老年人（7.0%）；在发生过跌倒的老年人中，有 52.6% 因此受伤[3 齐士格等，2018](http://chinaepi.icdc.cn/zhlxbx/ch/reader/view_abstract.aspx?file_no=20180410&flag=1)。这组数字提示：摔倒并不只发生在“无人照顾”的老人身上，但缺少身边人照应的老人，摔倒风险更高，被发现得更晚，后果也更重。

更值得强调的是，摔倒本身多数并不直接致命，真正的危险来自摔倒之后长时间无法自行起身、又无人发现。一个人在地上躺多久，最关键的变量是“能不能被及时发现”——这恰恰是当前最不可控的一环，也正是本项目要压缩的那一段。早在 1981 年，《英国医学杂志》（BMJ）对 125 名 65 岁以上居家摔倒者的一项调查就发现，其中 20 人躺在地上超过 1 小时，这批人中有一半在摔倒后 6 个月内死亡；同一研究还发现，跌倒者一年内的死亡率是同年龄、同性别对照组的 5 倍，并指出居家跌倒在老年人中常常本身就是“健康状况已经较差”的信号[5 Wild 等，BMJ，1981](https://www.bmj.com/content/282/6260/266)。换句话说，这项研究能支持的是“摔倒后长时间无人发现，后果往往很严重”，而不是“躺得越久就一定致死”——我们把它作为问题严重性的依据，而不是因果证明。所以我们并不声称“报警快就一定没事”：本项目要做的是一件很具体的事，把“从摔倒到被发现”这一段从几小时压缩到几秒，让它不再成为决定后果的那一环。

**二、现有方案的局限**

| 方案 | 是否需佩戴/改造 | 覆盖范围 | 部署成本 | 实时预警能力 | 主要短板 |
| --- | --- | --- | --- | --- | --- |
| 人工巡查 | 否 | 受人力限制，夜间与无人值守时段基本失效 | 人力成本持续投入 | 差 | 无法 24 小时覆盖，事发过程无记录 |
| 可穿戴设备（手环、跌倒报警器） | 需长期佩戴、需定期充电 | 仅佩戴者本人 | 中等 | 较好 | 依从性差：实际使用中容易被摘下或忘记佩戴，关键时刻反而没戴在手上；佩戴不适感较强，对记忆力、行动能力较弱的老人不够友好；易受日常动作干扰而误报 |
| 专用传感器（毫米波雷达、压力垫等） | 需安装改造 | 单个房间，多房间需多套设备 | 高 | 好 | 造价高、难以规模化；需逐房间安装调试，老旧住宅与既有机构改造难度大；设备位置一旦变动通常要重新标定 |
| 现有视频监控（大多数机构的现状） | 否 | 广 | 低（已建成） | 几乎没有 | 只能事后回放，缺乏事前与事中预警能力 |
| **本项目：纯软件视觉方案** | **否，复用存量摄像头** | **摄像头可见范围** | **几乎为零（不新增硬件）** | **有：自动识别 + 声音报警** | 受光照、遮挡、视角影响，需通过数据与阈值持续优化；卫生间等私密空间不宜安装，覆盖范围受摄像头位置限制 |

综合来看：人工巡查依赖持续的财力人力，可穿戴设备要求老人改变生活习惯，专用传感器需要一笔不小的硬件改造费用；而全国范围内已经建成的海量监控摄像头，目前基本只承担“事后回放”的职能。本项目要做的，就是把“已经存在的摄像头”变成“会报警的眼睛”。

需要说明的是，卫生间等私密空间不适合安装摄像头，这部分盲区不在本方案的覆盖范围内，仍需依靠其他监护方式兜底；本项目面向的是家庭与养老机构中最主要的活动区域，可与可穿戴设备、紧急呼叫等方式配合使用。

**三、项目价值**

1、**社会价值**：为独居老人家庭、社区养老服务中心、养老机构值班室提供一套低成本、非接触的摔倒预警手段，把“发现时间”从数小时压缩到数秒，为救援争取时间，进而降低摔倒后的致残与死亡风险。同时我们坚持一条原则：技术用来守护老人，而不是用来监视老人。

2、**经济价值**：方案为纯软件形态，复用既有摄像头与普通计算机，无需新增传感器、无需布线改造，智慧养老改造的边际成本趋近于零，便于在预算有限的家庭与基层机构中推广。

3、**技术价值**：验证“轻量目标检测模型 + 连续多帧判断”在低算力条件下的可行性，沉淀一套可复用的参考实现（帧序列—检测—判断—报警）。该实现不局限于摔倒检测，后续可迁移到逗留、闯入、攀爬等其他异常行为识别任务。

### 创新点

1、**存量摄像头复用、纯软件旁路部署**：系统不新增任何传感器，直接接入已有摄像头（USB 摄像头、本地视频、网络摄像头），以软件方式旁路运行，不改变原有设备的安装方式与运行策略，接入时只需要一路可用的视频流。老人无需佩戴设备，机构无需布线改造，部署成本趋近于零。

2、**“单帧检测 + 多帧确认”的两步判断（针对误报的关键设计）**：摔倒与“蹲下、坐下、弯腰拾物、躺卧休息”在单帧画面中高度相似，仅靠单帧检测极易误报。本系统在 YOLOv8 的检测结果之上再加一层轻量的多帧判断：①检测框宽高比发生突变（由“竖长”变“横宽”）；②检测框中心点高度较历史均值骤降；③最近一段时间内连续命中的帧数达到阈值。三者同时满足才触发报警。该设计不增加训练成本，却能显著减少“蹲下系鞋带引发的报警”。判断逻辑示意如下：

```text
每一帧: YOLOv8 推理 -> 检测框(类别, 置信度)
                |
                v
        置信度筛选 (confidence >= 阈值)
                |
                v
        连续多帧判断，三项条件同时成立:
          (1) 框宽高比 >= 阈值 A           —— 由“竖长”变“横宽”
          (2) 框中心高度较历史均值下降 >= 阈值 B —— 身体高度快速下移
          (3) 最近一段时间内连续命中帧数 >= 阈值 N —— 排除偶然的误判
                |
        +-------+-------+
        |               |
      满足             不满足
        |               |
        v               v
  触发声音报警      仅显示检测框，继续观察
  (设计防抖，避免重复报警)
```

上图中的三个阈值（宽高比、中心高度下降幅度、连续命中帧数）都是待定参数，具体取值由第二阶段的对比实验确定，并在界面中开放调整，此处不写死。

这一判断方式并非凭空设想：公开的 [7 UR Fall Detection Dataset](https://fenix.ur.edu.pl/~mkepski/ds/uf.html) 在发布数据集时，就把“检测框高宽比”“检测框占空比”等几何特征一并提供（需要说明的是，这些特征是从该数据集的深度图数据中提取的，并不是从彩色视频里算出来的），说明用目标的几何形态变化区分“跌倒”与“日常活动”是该领域已有的做法；本项目的差别在于把这套判断搬到普通彩色视频上，直接由 YOLOv8 的检测框计算得出，不需要任何额外硬件。

3、**参数全可调、报警可解释**：置信度阈值、连续帧数、报警冷却时间、静音开关均可在界面实时调整；界面同步显示检测框、类别与置信度，并记录触发报警的具体画面与分数，使报警原因可回溯。

### 研究内容

本项目要做的事分两块：一块是**模型能不能认得出摔倒**，另一块是**系统能不能真的用起来**。整体结构如下：

```text
[输入层]     图片文件(jpg/png)  |  视频文件(mp4/avi)  |  摄像头（USB / 网络摄像头）
                                        |
                                        v
[统一帧序列]  抽帧策略 -> 缩放 -> 归一化（三种输入共用同一套流程）
                                        |
                                        v
[检测层]      YOLOv8 推理 -> 检测框 + 类别 + 置信度
                                        |
                                        v
[判断层]      置信度筛选 -> 宽高比突变 + 中心高度骤降 + 连续多帧确认 -> 摔倒判断
                                        |
                                        v
[服务层]      FastAPI 接口 + 事件记录（时间戳 / 触发帧 / 置信度 / 报警冷却）
                                        |
                                        v
[界面层]      Vue 3 界面：检测框叠加 / 置信度显示 / 声音报警 / 参数面板 / 运行日志
```

**1、开发环境与基线。** 统一 Python 版本与依赖（PyTorch、Ultralytics、OpenCV、FastAPI 等），加载 YOLOv8 官方预训练权重，跑通“输入图片—推理—输出带标注框的结果”这一最小闭环；同时实测三台带 RTX 5060 的机器和一台无独立显卡的机器各自的推理耗时与显存占用，弄清本地算力能支撑到什么程度。这一步的结果将作为后续所有实验的基准线。

**2、数据与标注。** 公开数据集在机位、光照、人群上都与我们的实际场景有差距，自采数据规模又有限，所以要把两者结合起来：一方面筛选与清洗公开数据（例如 UR Fall Detection Dataset、Le2i、Multiple Cameras Fall Dataset 及公开平台上的跌倒检测数据）；另一方面由团队成员作为志愿者，在宿舍、走廊、楼梯口等场景拍摄“摔倒、坐下、蹲下、弯腰拾物、躺卧、快走”等动作，覆盖昼夜光照、远近景与正侧视角，并有意识地加入遮挡与多人同框画面。所有数据统一为 YOLO 标注格式，按 7:2:1 划分训练集、验证集与测试集，并形成一份可复核的标注规范，把“不同人标注结果是否一致”也纳入检查。

**3、模型训练与评测。** 以 YOLOv8s 为主模型，对输入分辨率、学习率、每次训练的数据量与数据增强方式做对比实验，观察不同设置下识别效果的变化；效果不够好时，还要能判断问题出在数据、模型还是判断阈值上。评测不只看整体准确率，另单独统计两项更贴近实际使用的指标：漏报率（摔倒却没报警）与误报率（没摔却报警）。

**4、多源输入与推理服务。** 图片、视频文件、摄像头三类输入的数据形态、节奏与异常情况各不相同，需要先把它们统一抽象为“帧序列”，再共用同一套处理流程。需要弄清抽帧与丢帧策略如何影响报警延迟、预处理与推理之间如何分工，以及前后端的接口约定与异常处理规则怎么设计，才能既避免为每种输入重复开发，又让实时输入不卡顿。

**5、界面与报警交互。** 界面要让人看得懂：检测框、类别、置信度与事件记录怎么组织，才能让使用者一眼看清发生了什么。报警则要在“漏报”和“误报”之间找平衡：用什么报警方式、冷却机制怎么设、参数面板给到多细，才能让不懂技术的使用者也能自己调整。

**6、系统集成与场景测试。** 实验室里能跑通，不等于真实场景里能用。需要把模型、服务与界面整合成可一键启动的完整系统，用测试用例覆盖三种输入方式与常见异常，并在不同光照、遮挡、多人、远近景条件下反复测试，弄清系统的能力边界，最后把适用条件与已知局限如实写进文档。

### 研究路线

总体研究思路是“先跑通、再跑准、最后跑稳”：先用官方权重跑通从输入到报警的完整流程，保证系统“能动”；再通过数据与微调把识别效果提高，保证系统“认得准”；最后通过连续多帧判断与参数调整把误报压下来，保证系统“用得稳”。技术路线如下：

```text
需求分析         数据准备           模型训练与调优        系统开发与集成       测试与总结
(功能清单)  ->  (数据集+标注规范) -> (微调+评测+对比)  ->  (服务+界面+报警) -> (场景测试+文档)
    |                 |                    |                    |                 |
 需求说明书      训练/验证/测试集      最优权重文件        可运行系统原型     结题报告+材料
```

**主要风险与应对预案：**

| 风险 | 应对预案 |
| --- | --- |
| 数据质量与规模不足（样本偏少、标注不一致） | 公开数据集与自采数据互补；制定标注规范并双人交叉复核；数据增强与多轮验证，用未见过的场景视频作测试集；若效果仍不理想，先交付“识别 + 规则判断”的可用版本 |
| 模型效果达不到预期 | 调整数据增强方式与训练参数，在 YOLOv8n 与 YOLOv8s 之间对比选择；必要时降低输入分辨率或减小每次训练的数据量；调整判断阈值，优先保证不漏报，再用多帧确认压制误报 |
| 本地算力与运行环境受限（单卡 8GB，驱动与框架版本要求较高） | 训练以 YOLOv8s 为主，必要时降低输入分辨率或减小每次训练的数据量；提前锁定并记录可用的驱动与 PyTorch 版本组合；训练全部在本机完成，不依赖云端算力 |
| 队员课业冲突导致进度延误 | 任务拆小、双周检查；数据采集与模型训练等关键任务提前启动；设定“最小可交付版本”（图片与视频输入可用、含标注与报警）作为保底 |
| 真实场景效果与测试集差距明显（含远景小目标与遮挡漏检） | 用真实摄像头在宿舍、走廊、家中补测；数据增强中补充小目标与遮挡样本；在文档中明确适用的拍摄距离、视角范围与已知局限 |
| 设备损坏或数据丢失 | 代码与文档及时推送到云端代码仓库，数据与模型权重保留移动硬盘备份 |

**保底方案（Plan B）：** 如果自建数据集上的微调效果不理想，就放弃数据集微调这一步，直接使用 YOLOv8 官方权重做通用行人检测，再叠加宽高比与高度变化的规则来判断摔倒。与主方案相比，它少了“用自采数据微调”这一环，识别准确度会低一些，但同样可以实现命题要求的全部功能（三种输入、标注框与置信度显示、声音报警），使项目在效果不理想时仍然有可交付的结果。

### 具备的研究条件

**1、团队与指导条件。** 项目组共 4 人，均为重庆大学大一本科生，由队长负责统筹与任务分配；项目配备 1 名指导老师，负责技术路线把关与疑难问题答疑。团队成员虽然年级低、科研经验有限，但学习能力强、课余时间相对充足，4 人均具备编程基础，并已形成查阅官方文档与阅读开源项目代码的学习习惯。项目工作按数据与标注、模型训练与评测、后端服务、界面与交互四个方面推进，由队长根据各人情况分配任务并跟踪进度；各环节互相评审、交叉参与，避免任何一项工作只依赖一个人。对 4 名大一学生来说，这同时是一次完整的科研训练——从查文献、采数据到跑实验、写文档，成员能力的成长本身就是这个项目要拿到的东西之一。

**2、硬件条件。** 团队 4 人中有 3 人的笔记本电脑配备 RTX 5060 独立显卡（8GB 显存），足以在本机完成 YOLOv8s 的微调训练与实时推理，项目全程使用自有设备完成训练，不依赖云端算力服务；另 1 台无独立显卡的机器用于前端开发、文档写作与低负载调试。此外配备 USB 摄像头一枚用于实时输入调试，手机可用于采集自建数据集；数据、模型权重与实验记录保存在本地磁盘，并定期备份到移动硬盘。

**3、软件与平台条件。** 项目完全基于开源生态，不产生软件授权费用：算法侧使用 Python、PyTorch、Ultralytics YOLOv8、OpenCV；服务侧使用 FastAPI；界面侧使用 Node.js 与 Vue 3（配合 Vite 构建、Naive UI 组件库）；开发工具使用 VS Code、Git 与 GitHub 进行版本管理。Ultralytics 官方文档、GitHub 上的开源摔倒检测项目、B 站与 CSDN 上有大量可参考的教程与代码，学习成本可控。

**4、数据条件。** 公开渠道可获得若干成熟的行人摔倒数据集（如 [7 UR Fall Detection Dataset](https://fenix.ur.edu.pl/~mkepski/ds/uf.html)、Le2i Fall Detection Dataset、Multiple Cameras Fall Dataset 及公开平台上的跌倒检测数据集），可满足模型微调的基本样本量需求；同时由团队成员作为志愿者补充拍摄模拟摔倒与近似动作视频，以贴合本项目的实际应用场景。二者结合，可在不依赖真实患者影像的前提下构建训练与评测数据。

**5、文献与资料检索条件。** 世界卫生组织、国家统计局、中国疾控中心等机构公开的统计与健康资料可免费查阅；Ultralytics 官方文档与 GitHub 上的开源项目提供了从数据标注、模型训练到部署的完整说明。

**6、时间与经费保障。** 项目周期约 9 个月，起止时间以平台要求填写的时间为准；4 人可利用课余时间与周末集中推进。项目经费按学校 SRTP 经费管理办法使用（详见文末预算）。

### 预期研究目标

**总目标：** 交付一个可运行、可复现、可演示的纯软件摔倒识别与报警原型——接入已有摄像头即可工作，识别到摔倒行为时在画面中标注位置、显示置信度并触发声音报警，同时配套完整的开发与使用文档，形成一份结论可靠的结题报告。
